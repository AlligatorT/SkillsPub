# ADR-0005: 提供全功能 TUI(反转"不做 GUI/TUI"非目标)

状态: superseded by ADR-0006 (2026-07-30)

## 背景

初版设计把 GUI/TUI 列为非目标(ADR 调研时认为 CLI + 薄 skill 层已够)。重新评估后认为:开关矩阵本身是强可视化场景,人工管理时不该被迫开一个 agent;而 CLI 的命令面已经定义清楚了全部操作,TUI 只是同一操作的另一个壳,边际成本低。

## 决策

- **提供 TUI(`skillspub tui`),全功能管理**:skill × agent 开关矩阵 + on/off,以及 bundle/tag/preset 的创建、成员管理、apply,与 CLI 命令面一一对应。
- **核心逻辑收进 library**:CLI 命令、TUI、薄 skill 层(通过 CLI)三个入口共用同一个 programmatic core,TUI 不自带业务逻辑。
- **实现语言 TypeScript/Node**:与 skill 生态(npx skills 等)同沟,用户必有 node;分发走 npm,`npx skillspub` 即跑;TUI 用 Ink(React 渲染 terminal UI)。
- 仍然**不做 GUI**(桌面/网页图形界面)。

## 后果

- CONTEXT.md 非目标中的"不做 GUI/TUI"收缩为"不做 GUI"。
- 不开 agent 也能人工管理 skills;agent 在场时走薄 skill 层调 CLI,两条路径操作的是同一份磁盘真相(ADR-0001),不冲突。
- 代价:实现量约翻倍;靠"core 是 library、TUI 纯壳"压住复杂度。
